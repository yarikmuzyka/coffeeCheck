# Design

## Context

- `app/new-lots/page.jsx` — серверний компонент. Він уже рахує відфільтрований список `lots` для вкладки «Новинки» (`filterAndSortLots`) і мапу `recommendations` з емодзі-позначками (`recommendLots` → `marker`).
- Клієнтських компонентів у проєкті мало (`app/components/ConfirmSubmitButton.jsx` тощо). Server actions `saveWishedLot` / `removeWishedLot` приймають `FormData` з `lotId`.
- Вимоги див. у `specs/new-lot-random-pick/spec.md`.

## Goals / Non-Goals

**Goals:**
- Миттєвий результат без перезавантаження і без нових запитів до БД.
- Логіку вибору покрити юніт-тестами окремо від UI.

**Non-Goals:**
- Зважений вибір (наприклад, частіше підкидати 🎯). Тільки рівномірний.
- Історія випалих лотів, анімація «рулетки», шеринг результату.
- «Хоба» на головній сторінці.

## Decisions

1. **Вибір на клієнті, кандидати від сервера.** Сторінка передає в клієнтський компонент `HobaPicker` легкий масив відфільтрованих лотів: `id`, `name`, `roasterName`, `originCountry`, `processNames`, `price`, `currency`, `productUrl`, `imageUrl`, `marker`, `isWished`.
   - *Альтернатива:* серверний вибір через URL-параметр `?hoba=1&prev=<id>`. Працює без JS, але кожен клік перезавантажує сторінку і заново тягне ~70 лотів і кави з БД. Відкинуто: «миттєвість» тут головне.
2. **Чиста функція `pickRandomLot(lots, previousId, random = Math.random)`** у `lib/random-lot.js`.
   - Якщо лотів 0, повертає `null`. Якщо 1, повертає єдиний.
   - Інакше вибирає рівномірно серед лотів, крім `previousId`.
   - `random` можна підмінити, тож функція тестується детерміновано.
3. **Картка результату — окремий легкий компонент**, а не перевикористаний `LotCard`. `LotCard` — серверний компонент із server-action формами; його не можна відрендерити в клієнті по кліку. Нова картка реюзає ті самі CSS-класи (`new-lot-*`, `new-lot-marker`) і додає модифікатор виділення.
4. **«♡ Хочу спробувати» через ту саму server action.** Клієнтський компонент імпортує `saveWishedLot` і рендерить `<form action={saveWishedLot}>` із прихованим `lotId`. Ревалідація сторінки оновлює пропси, але не скидає клієнтський стан. Тому компонент зберігає лише `pickedId` і бере лот зі свіжих пропсів: картка лишається на місці й одразу показує «♡ У списку».
5. **Розміщення:** кнопка «Хоба» стоїть праворуч у рядку з фільтрами або одразу під ним. Картка результату з'являється між фільтрами і списком, кнопка закриття «×» у її куті.

## Risks / Trade-offs

- [Відфільтрований список змінився після ревалідації і випалого лота в ньому вже немає] → Картка просто зникає. Наступне «Хоба» вибирає з актуального списку.
- [Розмір пропсів: до ~70 лотів серіалізуються в HTML] → Лише потрібні поля. Це кілька КБ.
- [`Math.random` не криптографічний] → Для вибору кави це не має значення.
